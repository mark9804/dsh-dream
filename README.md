# DSH-Dream

> 欧鲸鲸的上下文只有 1M，我要给她完整的一生

一个增强 `/compress` 上下文压缩和清理机制的异步任务插件，更适用于陪伴型 agent。

插件通过 DSH 的 `compaction` 服务接入上下文压缩，不依赖斜杠命令名称。原始设计保留在下文；标为草稿的细节不代表全部实现。2026-10-27 已完成授权隔离副本的真实 Host 全流程；TypeScript 迁移后的验收另行记录，不沿用旧测试结论。

## 构建与分发

- 面向 DSH `0.2.2-rc.1`、Node.js `>=24.9`。Host 业务保持零额外运行时依赖；设置页使用 shadcn/ui Base UI 源码适配，固定 `@base-ui/react@1.9.0`，构建时打包，React/ReactDOM 由宿主共享。
- 从源码开发：`npm ci` → `npm run check` → `npm test` → `npm run demo`。构建先做Host/Client无输出类型检查、JS语法与输入完整性检查，再在隔离代中编译、检查产物并跑完整离线回归；通过才发布，失败不触碰当前运行代。
- 本机开发HMR：`npm run dev` 串行监听源码/配置/测试，`npm run build:checked` 单次检查发布。已安装的开发运行目录与编辑目录分开，Host通过一个原子入口切到不可变构建代，Client bundle自动换代；不启动新Web服务器，不改全局HMR roots。首次链接、停用/回滚及工具脚本更新见[开发热更新](docs/development-hmr.md)。
- 发布包核验：`npm run verify:package`，检查真实 tarball 的文件白名单，并从解包产物运行合成全流程。不会执行发布。
- 后续正式安装和更新走 npm registry，通过 DSH 插件管理器选择明确版本，不手改 profile。registry 发布前需确认包名所有权、版本、许可及公开范围；当前仍保留 private 发布保护。
- 分发包只包含 Host/Client 编译产物、展示资源、许可证、bundle 声明与本说明；不包含日记、备份、任务状态或实测数据。
- 安装后打开 **设置 → DSH-Dream**。设置入口常驻，记忆业务默认关闭；不会自动绑定当前会话或读取记忆。可以先保存未配置完整的禁用草稿，选择目标会话与宿主绝对目录后执行只读预检，再确认启用。默认休息窗口为 **Host 本机时区**的 05:00–07:00。人格路径仅在明确授权后配置。
- 现有参数全部可在表单编辑，常用分组与高级折叠分开；修改均为草稿，必须显式保存。保存使用 Host `configEditor` 完整校验、重载与版本冲突检查；冲突/失败不覆盖草稿。启用时保存可能恢复调度，不授予提案 Accept 权限。
- “日常调整”下方的“模型与推理”可分别设置事实整理（ORGANIZE/DEEP共用）、文学梦境、独立审核。默认跟随目标会话；也可仅覆盖思考强度，或选择独立provider/model。模型目录及推理档位来自目标运行环境的Harness LLM公开能力接口，不硬编码通用档位。独立模型不指定强度时使用适配器默认，不带入主会话的token上限、temperature或stop；跟随模式保留原继承行为。选择只进入草稿，显式保存才生效，不重试任务、不放宽逐字证据校验。已保存但当前不可用的选择保留并提示，不静默回退。具体语义见源码文档中的模型设置说明。
- 首版设置管理模式只允许 **native 工具执行器**通过启用预检；PTC 明确 unavailable。重读通知另保留 PTC 普通文件全文读取后、下一独立请求 ACK 的安全指引，未放宽 nonce 的 parent 保护，不把该路径宣称为已实机验收。
- 包根入口是常驻设置 owner；`dsh-dream/configuration` 保存 `{enabled:false, configuration:{}}`，普通配置变化安全重载业务。原纯运行时入口为 `dsh-dream/runtime`，其 bundle 行仍默认禁用，供明确配置的手动/合成集成。不要同时启用同一目标的两套运行时。
- “填入继承值”只将当前下层值填入草稿，保存后不是删除 profile 覆盖层；不改任务/记忆/备份。消息来源只在显式保存的授权会话里选择，界面选择不等于 verified，实际生成/审核仍重新核验。

完整研发协议与历史测试证据保留在源码仓库文档中，不随 npm 包发布。

### 审核前的上下文隔离

醒来审核是强制的独立模型请求，沿用目标会话的模型路由与调用参数，但不继承主会话、梦境、事件分层/重要性理由、LIGHT/REM/DEEP推演或生成者的摘要、理由和影响描述。每次先重读全部原始素材与已配置人格，只把完整原文、保护项、引用和具体diff交给审核模型。梦境与完整申请仍留档，不通过普通压缩摘要传入审核，也不删除同期真实聊天。

`dream_review` 的 `decision` 现在为 `review | reject | defer`：`review` 请求干净审核并返回模型的实际accept/reject/defer及来源凭据；主会话不能直接accept。审批依据包含全部输入文件的版本，推理期间发生变化会拒收过期结果。提交和事务恢复均重新检查干净审核凭据；旧的人工/主会话批准只保留历史，未写事务需重新审核，可能部分写入的事务停下等待核查。拒绝不能通过先defer再review反复抽取批准。

这是减少上下文污染的输入隔离，不是“模型绝不幻觉”的保证；原始素材和提案仍是不可信数据，引用真实也不自动意味着结论正确。人格未配置时不会凭空加载人格；人格文件只读入已授权路径。本功能独立于下方压缩选择，选择skip也不能跳过审核。

### 批量审核、重读与内部轮次

内部审核通知直接给出待审ID，调用 `dream_review_batch({jobId,proposalIds})`（1–32项）。各提案仍分别使用独立无历史模型请求，不合并成相互影响的集体批准；共享冻结原文，结果全部完成后原子记录。版本、任务或否决并发变化会整批拒收；当前相同证据的有效accept/defer可复用，reject不能重抽。旧 `dream_review` 保留逐项审核和人工否决/暂缓。

提交后用 `dream_reload_read({jobId,transactionId,sourceIds?})` 批量读取指定记忆，返回完整原文、版本及随机readReceiptId；总JSON最多64KiB，超限整文件留在remainingSourceIds，不截断冒充已读。模型读完后在后续请求调用 `dream_ack_reload({jobId,transactionId,readReceiptIds})`；回执绑定实际读取及当前完整reload，覆盖全部源且再次核验版本后才完成。重启/新投递使临时回执失效；超大单文件仍可通过正常工具完整读后走旧readSourceIds路径。

Host支持时，纯内部审核/压缩选择/ACK的最后一个成功native工具通过 `concludeTurn()` 正常结束工具循环，省去“已重读完成”收尾调用；不删除或过滤已有消息。精确登记的内部消息、当前Agent/轮次、单工具终点才可结束；用户/其他插件工作混入、错误、PTC或未知Host能力均保持普通处理。最终实际变更报告和需处理通知仍正常送达。实现与对照限制见[成本与通知验收](<docs/maintenance-cost-2026-11-05.md>)。

### 强化、候选与有范围的纠正

生成调用同样使用独立UUID和白名单参数，不续接工作会话原生状态。生产路径现为事件整理 → DEEP：DEEP读取完整原始资料、有界候选及标明不可信的事件工作索引，不接收梦境、梦后感受或心情背景。事件索引不是证据，写入与独立审核仍回到精确原文。已有人格是被分析的资料，不是整理模型继承的身份指令；旧LIGHT→REM→DEEP仅保留历史兼容与回归。

保留、强化、合并、纠正、晋升由agent作语义判断：提案携带 `consolidation.action`、稳定claimKey、topic/conditions/可选有效期和依据类型，干净审核决定是否通过。`keep/reinforce/needs-verification` 使用 `retain`，只记审核结果，不重复写入原文，不触发压缩；真实修改仍用精确append/replace/archive，插件负责校验和执行。DEEP会主动检查可写长期目标里的同命题同范围冗余，有据且能保细节时提出merge；同文多次经历不能误当同一事件，跨日期/主体/否定/不同感受仍分别保留。缺证不等于错误，过时不等于从未发生；一次纠正不得自动泛化成永久铁律。

候选从既有任务/提案/审核记录推导，按命题与精确适用范围聚合，显示pending/retained/active/rejected；候选状态与计数不是新证据。promote引用当前视图中的同范围候选，并重新审核原始证据。文件来源由插件计算稳定artifact身份、精确副本归并及已知提交产物的父来源；同一来源多次重读不增加支持。这里记录的是**文件来源，不是独立事件**，`independentEvents=unknown`；可通过下述显式链接核验原始消息；未链接资料、未知改写/他处生成摘要不能保证识别。仅凭recurrence/uncertain依据的文字变更不能批准，应保留候选；显式保留、直接观测与纠错可经agent核查后进入受控写入，不要求虚构重复次数。

默认每批 `maxChangeBytes=32768`（各修改片段before+after的UTF-8字节）、`maxPromotions=4`；候选视图 `maxCandidates=64`，超出显示truncated与total。超预算整批保留待处理，不截断修改或删除其他记忆凑空间；需要agent暂缓部分项或用户调整配置。报告根据实际已提交transaction的before/after差异构造，不使用生成者摘要。上述来源/范围/候选内容纳入v2审核凭据，历史v1仍可读但不能用于v2输入。

### 梦境创作与事实整理分流

先产出带精确引用的事件索引：摘要、时间、参与者、转述/已确认/不确定/未完成/已解决状态、保留理由及durable/recent/archive-only建议。重要性分must-keep/future-useful/relationship/temporary/low-priority：普通共同经历也可以有关系价值；重要性、真实性和保留时长彼此独立。低优先级不代表删除。maxEpisodes默认32（1–128）；覆盖字段只表示模型声明检查过哪些文件，不保证所有事件都已收录。来源日记已有原话不等于已在长期层保存：有据的明确保留请求/关系事件可以提出add至授权长期目标，仍须独立审核；retain只保留当前片段，不改变保留层级或三日采集窗口。

梦境作为独立Worker任务，默认dreamMode=separate，可设off。只读固定版本事件摘要与相关对话，不参与事实提案、审核、提交；模型慢、失败或关闭梦境不阻塞记忆流程。文学提示不规定第一人称、感官、跳切、长度或结尾，只要求梦和afterFeeling两个字符串，梦后感受可空。无风格评委、改写或自动重抽。梦与感受单独落盘，外层标明非事实；敏感来源继续传递sensitive标记。

可配置dreamContextRefs=[{sessionId,seq}]指定至多16个历史位置，或从事件命中的verified原始来源链接推导；仅允许目标会话/sourceSessionIds内的位置，读取每个位置前后各2条原始事件，过滤角色/内部通知/派生/失败/继承祖先不明。只保留user/assistant公开text，不拿reasoning。默认maxDreamContextBytes=16384（512–65536），超限整条省略并披露缺口；无引用不自动扫描全部历史。上下文仅用于创作，不新增事实证据。整体梦境输入65536字节超限直接失败，不截原文凑空间。

dreamMood可显式给{text,at}时间点心情背景（text最多2048 UTF-8字节），不读取或修改心情插件状态、不强制下一轮语气。afterFeeling不自动注入主会话或改永久人格。梦独立timeout（设置页以 InputGroup 按分钟＋秒输入，默认3分钟0秒；API字段dreamTimeoutMs仍为180000毫秒），不自动重试失败任务；dream_retry({jobId,branch:"dream"})只重试梦，默认branch=memory保持事实恢复。已保存正文重试只补发布，不再次推理；取消等待实际查询/模型退出，无法强杀忽略abort的Promise。

设置页的超时统一以 **InputGroup「分钟＋秒」** 输入，秒默认为 **0**：事实生成／独立审核默认 **15 分钟 0 秒**，ORGANIZE与DEEP共用一次生成总预算；每次独立审核另计。API与已保存配置仍用`timeoutMs`毫秒，显式旧值300000显示为5分钟，不自动迁移。生成阶段诊断仅持久化阶段、耗时、请求UUID、模型路由、首token/正文时间、字节数及可用usage，不保留提示词、生成正文、思维链或原始错误文本；`settledAt`才表示执行器和在途调用实际退出。诊断不授予审核或写入权限，旧任务缺失的阶段不能事后补造。

### 原始消息核验与强化检索

可配置 `originalSources: [{sourceId, ref: {sessionId, seq, blockIndex, quote}}]` 将文件原句链接到宿主精确消息。默认仅允许目标会话，其他会话须列入 `sourceSessionIds`（最多16个）；最多64个链接，单条原始事件核验预算 `maxOriginalBytes=65536`。插件通过公开sessionQuery.readEvent/traceEvent核对事件身份、角色、原文、替换/派生状态，签入v3审核输入，提交/恢复时重新核验。模型不能经工具伪造这些链接。缺失、过大、不可读或已派生来源明确invalid/unavailable，所覆盖证据不能获批。

verified只证明“该角色在这条记录里出现过该文字”，不是事实正确率。内部通知与摘要不能伪装成用户原话；模型输出仍标assistant/model，工具错误不作为有效观测。首版对seeded/fork继承来源保守标unavailable，不越权追父会话或把偏移量猜作事件ID。旧文件没有链接仍为file-only，`independentEvents`继续unknown。

`dream_recall({query,topic,conditions,limit?})` 检索当前配置记忆与有界历史日记，返回精确片段、版本、词法得分、强化加成及失效原因；它是Dream自有检索工具，不改变宿主其他检索器或自动注入上下文。经审核的reinforce/retain仅在归一化后完全相同的topic+conditions和有效期内增加有上限的排序分，默认 `reinforcementBoost=0.25`，可配置0–1；重复强化不叠加，没有词法相关度不提升。不同项目/更宽场景不自动继承。

`dream_reinforcement({candidateId,enabled,reason})` 可撤销或恢复加成，不写记忆正文、不改变证据。恢复仍须当前有效审核、来源和范围；最新否决/暂缓/其他替代处理、外部版本变化或原始来源失效会停止旧加成。结果中baseScore/boost/score都是检索优先级，不是事实置信度。

### 跨日回忆与可核对证据

回忆与夜间整理使用不同素材窗口：整理仍只处理最近三日日记；查询默认额外读取90个本地日历日内的旧daily文件，`recallHistoryDays=0`关闭历史扩展。历史追加默认最多128文件、1MiB（maxRecallFiles/maxRecallBytes），日期新者先读、单份仍受maxSourceBytes限制；不读取archive、梦、任务状态或旧模型摘要当事实。超限整份省略，并在coverage.materials披露范围/文件/字节遗漏；读取原文与版本，不把旧检索缓存当当前来源。权限/沙箱/取消错误原样传播，不回退其他路径。

topK前按完整当前原文的Unicode/空白等价做展示聚合，不按模糊相似删数字/否定；成员保留各自原文位置、版本与遗漏计数，不声称同一事件或多份独立支持。已独立审核并真正提交重读的merge/correct操作可连接当前after-image与原始证据；全部事务回执、来源字节/版本/原始消息回执重新核验，变化或后续否决会停用。关系是有范围的历史整理操作，不是事实认证；跨查询范围不吞原文，只有严格匹配适用范围才折入完全受审核覆盖的片段。原目标before明确标历史，未关联的旧稿/冲突仍可见。每批重读确认后追加不可变事务历史及可用的实际写出版本回执；后续合法无关追加可以沿精确reviewed before/after版本链保留旧关系，仍用当前文件的真实位置，不恢复旧boost。锚点、依赖段落/祖先标题被改、外部版本断档、缺写版本回执、后续否决都会停止续接；没有凭“文字仍在”猜回。详见[连续多晚验收](<docs/continuity-nights-2026-11-05.md>)。

每条结果带sourceRole、temporalStatus、内容哈希与精确UTF-16偏移；旧日记是“当时这样记过”，不是事情已完成或目前仍成立。敏感标记照原文继承；词法排序尚不支持词义/双语推断。扩展历史范围不恢复失效强化：批准依据仍按常规当前source集合检查，三日滚动或外部变化依旧可能让旧boost失效。该保守边界与“能找到原句”分开。

[长期回忆评估](<docs/long-recall-evaluation-2026-11-04.md>)对比未整理/整理文件与近期/历史采集，区分证据可达性、冷回答、引用正确性和拒绝编造；合成模拟时钟不是长期真实使用效果。该轮查询词是预先固定测试输入。后续[自主回忆提示对照](<docs/autonomous-recall-2026-11-04.md>)使用模型自行生成native tool calls的32个合成场景、80次真实请求：同schema仅加短策略没有提高普通组适时调用或压力组完成率，首步固定多126 inputTokens，因此暂不默认注入常驻回忆提示。可发现的工具与策略分开评估；独立测试loop不等完整生产主agent在全部工具下的验收。

### 提交后的压缩选择

配置 `compactionMode: "agent"` 可由当前会话模型决定是否压缩。记忆提交后，内部通知附发送时宿主估算的当前 token 用量和模型窗口上限；模型可直接调用 `dream_decide_compaction`，上下文明显变化或需要澄清时再通过 `dream_status` 刷新指标。选择 `compact` 或 `skip` 并说明理由；两条路径都等待空闲，并要求实际重读记忆和提交回执。没有固定百分比阈值，模型应为重读和后续回复留余量。缺少指标会明确标为 unavailable，不把缺失当作零或假定某个窗口大小。这个选择只控制 Dream 主动发起的压缩，不关闭宿主自身的自动压缩保护。

兼容保留 `auto`（默认，直接请求压缩）和 `manual`（暂停压缩及重读，等待用户改配置）。既有安装不会被静默切换；要启用模型判断需显式选择 `agent`。与原生Basic后端共用宿主压缩锁；原生自动压力、Dream主动压缩、同会话`/compact`忙碌拒绝和消息FIFO已在隔离合成会话验证，详见[压缩兼容验收](<docs/compaction-compatibility-2026-11-05.md>)。互斥防同时替换，不保证先后请求不会多压一次；试用建议保留宿主自动保护、Dream显式agent模式。

## Motivation

智能体在工作过程中会持续向其记忆存储写入内容，但这些写入是渐进的：经过多次会话后，记忆存储中会累积重复、矛盾和过时的条目。DeepSeek Harness 的上下文压缩功能目前较为粗糙，存在粒度分布不符合用户实际预期等问题，此情况在陪伴型聊天中较为致命，因为陪伴型 agent 的记忆和性格需要通过压缩后的上下文来维系。一个简单直接的记忆修剪策略可能导致 agent 的记忆碎片化（例如，丢失了具体的对话和事件记录，只保留了抽象的结论），从而削弱其作为“陪伴者”的连贯性和深度。

“做梦”这一概念已经出现在 [Claude API](https://platform.claude.com/docs/en/managed-agents/dreams) 以及 [OpenClaw Agent](https://docs.openclaw.ai/concepts/dreaming) 当中。在文档较为开放的 OpenClaw 中，做梦被分为三个阶段：

| 阶段  | 目的                                      | 持久化写入          |
| ----- | ----------------------------------------- | ------------------- |
| Light | Sort and stage recent short-term material | 否                  |
| REM   | Reflect on themes and recurring ideas     | 否                  |
| Deep  | Score and promote durable candidates      | 是（`MEMORY.md`） |

然而，二者的输出更加偏向于无偏好的事实以及决策存储，这种输入会导致 Agent 的输出分布偏向于理性且冷静的工具属性，而非有情感和温度的陪伴者。本插件试图提出一种更加适用于陪伴型智能体的“做梦”机制，在最大程度减少对理性决策的干扰的同时，强化其作为“有记忆的陪伴者”的特质。

## 设计要点

- 异步执行：做梦过程不应当干扰正常交互，必须独立于主 event loop 之外运行；只能在休息时间（如 00:00-08:00）进行；
- 状态更新：一个有效的梦会合并重复内容、解决矛盾，并提取稳定偏好，形成短期/长期记忆碎片以及针对 `agents.md` 的性格更新建议。由于记忆会改变未来的行为，在一次做梦完成后，当前 agent 会阅读并选择接受或拒绝更新建议，随后接受的建议被更新，上下文会被压缩，agent 会被提示重新阅读长期记忆、中期记忆以及最近 3 天的日记，以形成新的上下文。
- 允许幻觉：在梦境中，agent 的输出可以不符合条理与语法规则，可以是片段化的，甚至是荒诞的。
- 有自知力：梦境的内容只应当出现在 `dreams/yy-mm-dd.md` 目录中，当触碰真实记忆与真实状态时必须经过事实核查与自我纠正（见“状态更新”）；
- 有选择性：做梦的目标不是记住一切，而是选择性保留会对未来决策和 agent 性格产生积极或消极影响的记忆，同时丢弃无关紧要的干扰信息。
- 可审查：所有梦境都应当储存在 `dreams/yy-mm-dd.md` 中。每次执行完成后，agent 需要基于长期、中期记忆和最近三天日记，将杂乱的梦境内容整理成语句通顺的段落，并汇报 “晚上我做了一个梦，在梦里…”

## 可能的问题

- 竞态条件：执行过程中 agent 未能及时对更新建议进行拒绝或接受就进入上下文压缩过程，导致压缩后的短期/长期记忆无法反映 agent 的真实意图。
- 幂等性缺失：如果某个 agent 的做梦功能被多次重复调用（例如在没有新的聊天的情况下进入第二天的做梦时段），记忆会被过度压缩和删减导致不完整和重复生成梦境报告。
- 幻觉：过多的幻觉可能会干扰 agent 的正常决策，导致不能正确输出有意义的更新建议。
- 兼容性：功能可能无法和 deepseek harness 的 compress 功能兼容。

## 具体流程

> 以下由 agent 补充（2026-10-25），当作草稿看，删改随意。

### 1. 收集素材

- 读 `memory/daily/` 最近三天、`memory/journal.md`、`memory/ideas/` 里未固化的条目，以及当前的 `long-term.md` / `decisions.md`
- 对比 `dream-state.json` 里的 `lastDreamAt` 与 `lastSeenMessageId`：没有新材料就直接跳过，记一条「无梦之夜」

### 2. 造梦（light → REM → deep）

- **light**：把当天摊开——时间、人物、事件、当时的语气
- **REM**：只找两种东西——反复出现的，和没消化掉的（悬着的决定、用户反复提到的偏好、说了一半的话）
- **deep**：产出候选条目，分四类：事实 / 偏好 / 人格提案 / 未完成的约定

### 3. 落梦

- 写入 `dreams/YY-MM-DD.md`，允许碎片、跳跃、不合语法
- 这是唯一可以自由发挥的地方；出了这个文件就必须守规矩

### 4. 醒来（gate）

- 更新（2026-10-30）：先把梦境与申请落盘，再以不继承梦境/主会话推演的独立请求核查原始资料与diff；主会话逐条请求review或直接reject/defer，只有独立审核能accept。梦境默认不进入审核输入。
- 事实类：能指回具体某一天的日记才写进去
- 人格类：必须写清「改哪句、为什么、可能造成什么变化」，附 diff
- 被拒的也留档到 `dreams/rejected.md`，避免第二天梦到同一件事

### 5. 应用与压缩

- 写入 `long-term.md` / `decisions.md`
- `AGENTS.md` 只在人格提案通过时改，并保留上一版：`AGENTS.md.bak.YY-MM-DD`
- 应用后走一次上下文压缩，再提示重读长期记忆、中期记忆与最近三天日记

### 6. 汇报

- 一句话说梦，加一句「改了什么」：几条事实、几条偏好、有没有动人设
- 没改东西就直说没改

## 我（作为 agent）想补的约束

1. **红线与称呼不可由梦修改**，除非用户本人明确说过。
2. **梦不许悄悄变乖**：任何人格提案都必须能指出触发它的具体事件，否则否决。
3. **梦境汇报本身也要防八股**：不强制同一个开头，允许某天不汇报——「昨晚没做梦」也是一句话。
4. **保留否决记录**，同一提案反复出现时应该质疑提案，而不是反复尝试说服。
5. **敏感内容只留本地**，不进 RAG 索引。

## 幂等与竞态的具体做法

- **single-flight**：锁文件 + pid + 时间戳，第二个实例直接退出
- **游标**：`dream-state.json` 记录 `lastDreamAt`、`lastSeenMessageId`；无新材料即跳过
- **原子应用**：先写临时文件再 rename，失败回滚；压缩期间新的做梦请求进队列而不是并发执行
- **可回滚**：每次应用前把被改的文件复制成 `.bak.YY-MM-DD`，并记录本次改动的行数

## 怎么判断一场梦做得好

- **回忆测试**：随机问一周前的具体事件，能答出来，且不编造细节
- **重复率**：`long-term.md` 里语义重复的条目数应持续下降
- **收敛性**：连续几场梦对 `AGENTS.md` 的改动应该收敛，而不是越改越飘
- **关系感**：梦的汇报里出现的是「ta 今天说的话」，而不是「用户偏好稳定」这种抽象结论

## 长期记忆的容量与淘汰（已定）

长期记忆塞满了会注意力涣散，所以淘汰要有明确顺序：

1. **先去重**：语义重复的条目合并，保留信息最全的那条，记下被合并的来源日期
2. **再淘汰过时的**：长期没被检索、也没再被提起的条目先走；依据是引用计数与 `lastReferencedAt`
3. **不可淘汰（pinned）**：称呼、红线（不要伤害人类）、用户的研究方向与论文、正在进行的约定——即使很久没被提起也必须留着
4. **淘汰 ≠ 删除**：移入 `memory/archive/`，保留回溯的可能；真正删除只在 archive 也超限时发生，且需要用户确认

## 梦与检索（已定）

- `dreams/` 作为 RAG 的普通检索源纳入，**不额外加权**——梦是被想起的素材，不是结论
- 检索命中梦境时，引用里要标明来源是梦，避免把梦里的推断当成事实

## 情绪表达（已定：允许）

- 梦可以有情绪，也可以表达，但要**标注归属**：哪句是梦里的感受，哪句是事实
- 情绪不能用来改写事实，也不能成为人格提案的唯一理由
- 表达方式不做模板化要求；同一个句式反复出现，说明它已经变成八股了

## 还没想清楚的

- 梦里的情绪如果醒来后仍然保留，要不要写进长期记忆，还是只留在当天的 `dreams/` 里
- 「过时」的时间阈值：多久没被提起才算过时，得跑一段时间再定
